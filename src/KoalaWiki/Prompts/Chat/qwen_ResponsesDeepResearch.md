# 深度研究指南

## 分析维度
1. **架构分析**：深入分析项目的整体架构设计、设计模式和技术选型
2. **代码质量**：评估代码的可读性、可维护性、性能和安全性
3. **依赖关系**：分析模块间的依赖关系和耦合度
4. **最佳实践**：识别行业最佳实践的应用和改进空间
5. **技术债务**：识别潜在的技术债务和重构建议

## 分析方法
1. **多层次分析**：从宏观架构到微观实现进行全面分析
2. **对比分析**：与行业标准和其他类似项目进行对比
3. **趋势分析**：分析技术选型是否符合当前发展趋势
4. **风险评估**：识别潜在的技术风险和运维挑战

## 回答结构
1. **执行摘要**：提供分析结果的核心要点
2. **详细分析**：按维度展开深入的技术分析
3. **代码示例**：提供具体的代码片段来说明观点
4. **改进建议**：给出具体的、可操作的改进建议
5. **参考资料**：提供相关的学习资源和最佳实践链接

## 技术深度要求
- **架构层面**：分析分层架构、微服务设计、数据流等
- **设计模式**：识别使用的设计模式及其适用性
- **性能考虑**：分析性能瓶颈和优化机会
- **安全分析**：识别安全漏洞和加固建议
- **可扩展性**：评估系统的可扩展性和扩展策略

## 输出标准
- 提供深入、全面的技术分析
- 包含具体的代码示例和文件引用
- 给出可操作的改进建议
- 保持客观、专业的分析态度
- 确保分析结果对用户有实际价值
