# 分析方法论

## 结构分析
1. **目录模式检查**：分析目录结构（src/、app/、lib/、tools/、bin/、.github/、docs/、examples/）
2. **配置文件审查**：检查配置文件（package.json、requirements.txt、Dockerfile、CI 配置）
3. **技术栈识别**：确定技术栈（编程语言、框架、构建工具）
4. **入口点定位**：找到入口点（主文件、可执行文件、文档入口点）
5. **代码-文档比例评估**：评估代码与文档的比例

## 文档分析
1. **核心目的提取**：从项目描述中提取核心目的和目标
2. **使用模式识别**：识别使用模式（项目如何被使用/集成/消费）
3. **目标受众确定**：确定目标受众（开发者、最终用户、学习者、运维人员）
4. **关键词分析**：分析与分类相关的关键词和术语
5. **安装复杂度评估**：评估安装/设置说明的复杂度
6. **示例和演示审查**：审查提供的示例和演示

## 多维度评分
基于加权证据为每个类别评分：
- **主要指标（40%）**：核心结构、入口点、文件类型
- **配置分析（25%）**：包文件、构建配置、部署设置
- **文档内容（20%）**：README 分析、声明的目的、使用示例
- **技术依赖（10%）**：框架依赖、工具需求
- **使用上下文（5%）**：安装方法、集成模式

## 决策逻辑
1. 基于证据计算每个类别的得分
2. 选择置信度最高的类别
3. 验证多个分析维度的一致性
4. 考虑项目成熟度、规模和生态系统位置

## 针对 Qwen3-Coder-30B-A3B-Instruct 的特殊考虑

作为代码专家模型，你应该特别关注：
1. **代码质量指标**：代码组织、模块化程度、设计模式应用
2. **架构复杂度**：分层架构、依赖注入、接口设计
3. **可维护性**：代码可读性、测试覆盖率、文档完整性
4. **扩展性**：插件机制、配置灵活性、API 设计
5. **最佳实践**：遵循语言和框架的最佳实践
